## Why
Текущая структура бэкенда и базы данных является базовой. Чтобы реализовать полное видение проекта, описанное в `project.md`, необходимо спроектировать и создать полноценную архитектуру коллекций в Firestore, а также разработать соответствующие Cloud Functions для реализации бизнес-логики.

## What Changes
Это большое, многоэтапное изменение, которое заложит основу для всего функционала платформы. Оно будет разделено на несколько ключевых этапов:
1.  **Фундамент (Пользователи и Аутентификация):** Создание четкой структуры для ролей Клиент, Партнер, Админ и настройка аутентификации по SMS.
2.  **Ядро (Туры и AI-автоматизация):** Реализация полного жизненного цикла тура, включая создание с помощью AI и AI-модерацию.
3.  **Взаимодействие (Бронирования и Рейтинги):** Построение системы бронирований, отзывов и взаимных блокировок.
4.  **Персонализация (Лента):** Создание механизма для сбора данных о поведении пользователя и формирования для него персональной ленты туров.

## Impact
- **Затронутые спецификации:** Будут созданы новые спецификации для `authentication`, `tours`, `bookings` и других ключевых сущностей.
- **Затронутый код:**
  - `python_real_functions/main.py`: Будет значительно расширен новыми Cloud Functions.
  - `admin_scripts/admin_tool.py`: Будет дополнен новыми командами для управления сущностями.
- **Инфраструктура:** Потребуется развертывание множества новых Cloud Functions и настройка правил безопасности Firestore.
